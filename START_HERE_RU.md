# SeatBook: запуск на Windows

## 1. Подготовка

Установи Docker Desktop, включи WSL 2 / Linux containers и запусти Docker Desktop. Для старта проекта через Docker отдельно устанавливать Go, PostgreSQL и Node.js не нужно. Нужен интернет для первого скачивания образов и Go-зависимостей.

Распакуй **весь ZIP**, открой папку `seatbook` в VS Code. В этой папке должны лежать `compose.yaml`, `go.mod` и `README.md`.

Открой терминал PowerShell в этой папке.

## 2. Запуск одной командой

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

Скрипт создаст `.env` со случайными ключами и запустит базу и приложение. Дождись сообщения `SeatBook is ready`.

Открой **http://localhost:8080**.

Если корпоративные настройки запрещают запуск PowerShell-скриптов, используй ручной способ:

```powershell
Copy-Item .env.example .env
docker compose up --build -d --wait
```

Не повторяй `Copy-Item`, если уже настроил `.env`: команда перезапишет его. Случайные ключи создаёт именно скрипт setup; ручной способ оставляет учебные значения из примера.

## 3. Что попробовать

1. Нажми **Sign in → New here? Create an account**.
2. Укажи email и пароль длиной от 10 символов, используя латиницу для простоты.
3. Открой мероприятие и выбери зелёное свободное место.
4. Нажми **Reserve this seat** — откроется список броней с таймером.
5. Нажми **Confirm (demo)** — бронь станет подтверждённой. Деньги не списываются.
6. Для другой брони нажми **Release seat** или подожди пять минут: место освободится.

Подтверждённые брони в этой учебной версии окончательные. Местный часовой пояс браузера используется для дат; сервер хранит время в PostgreSQL `timestamptz`. Цены указаны в тенге.

## 4. Администратор

Выйди из обычного аккаунта и войди:

- Email: `admin@seatbook.local`
- Пароль: `SeatBookDemo2026!`

Это локальный учебный аккаунт. В меню появится **Studio**. Создай мероприятие: название, описание, будущая дата, цена, число рядов и мест. Сетка мест создаётся автоматически вместе с событием.

Если поменяешь пароль в `.env` до первого запуска, используй новый. Изменение `.env` после создания аккаунта не сбрасывает его пароль.

## 5. Остановка и повторный запуск

```powershell
docker compose down
```

База сохраняется. Для следующего запуска:

```powershell
docker compose up -d --wait
```

После изменения Go/HTML/CSS/JS пересобери приложение:

```powershell
docker compose up --build -d --wait
```

## Если не запускается

**Cannot connect to Docker daemon:** запусти Docker Desktop и дождись готовности.

**Порт 8080 занят:** в `.env` измени `APP_PORT=8082`, затем выполни `docker compose up --build -d --wait`. Открой `http://localhost:8082`.

**Порт 5434 занят:** если Go тоже запускаешь в Docker, убери у сервиса `db` раздел `ports` — приложение использует внутренний порт 5432. Если запускаешь Go локально, измени внешний порт и `DATABASE_URL` согласованно.

**403 untrusted request origin:** открывай через `http://localhost:8080`, а не через `127.0.0.1`, либо настрой `APP_ORIGIN` под используемый адрес. Для Compose порт берётся из `APP_PORT`.

**База не принимает пароль после изменения `.env`:** пароль уже записан в существующий том. Верни старое значение или измени пароль внутри PostgreSQL. Не удаляй том, если нужны данные.

Посмотреть ошибки:

```powershell
docker compose ps
docker compose logs --tail=100 app db
```

Полный сброс учебных данных (удалит все аккаунты, события и брони):

```powershell
docker compose down -v
```

## Проверка проекта

```powershell
docker compose -f compose.test.yaml up --abort-on-container-exit --exit-code-from test
docker compose -f compose.test.yaml down
```

В тестах есть 20 одновременных запросов на одно место: должна появиться только одна бронь. Отдельно проверяются повторные запросы с одним ключом и гонки при истечении срока.
